# Agent v1 · 需求规格（SDD-Spec）

> "小屋 DJ"：自然语言描述听歌需求 → 多 Agent 协作检索本地曲库 + 歌曲海 → 流式输出推荐 + 一键播放。
> 上游决策：交接文档 §14.1；曲库供应链 v1.2~v1.4（歌曲海为唯一外源，试听层）。
> 用户硬性要求：多 Agent 协作、ReAct、Reflection、任务拆分、记忆机制、Agent Tools。

## 1. 背景与问题

1. 歌曲池已扩充（本地 184 首 + 歌曲海联网源），但发现音乐仍靠"搜索 + 推荐页"，缺乏"说一句话就给我安排歌"的智能化体验。
2. Spring AI 1.0.0 已随 Boot 3 升级引入（OpenAI starter，默认智谱端点），具备落地条件。
3. 用户已提供智谱 API Key；资源包主力模型 `glm-4.5-air`（12M tokens，推理模型）。

## 2. 目标（Goal）

1. 搜索页/全局入口的"小屋 DJ"对话：一句话描述（场景/心情/歌手/风格）→ 流式返回串场词 + 歌曲卡片 → 点卡片即播、可整组入队。
2. 检索同时覆盖本地曲库与歌曲海，卡片带来源标识；全程无幻觉卡片（两段式：卡片只认工具返回的引用）。
3. 多 Agent 过程可视化（正在理解需求/正在检索歌曲海…）。
4. 未配置密钥时优雅降级提示，不影响站点其他功能。

## 3. 用户故事

1. 听众说"来点适合下雨天听的歌"，看到 DJ 的串场词和一组混排卡片（本地+歌曲海），点开就听，还能"全部加入队列"。
2. 听众追问"换成周杰伦的"，DJ 结合上下文重新检索。
3. 开发者能在 SSE 事件流里看到 Agent 各阶段与工具调用过程，便于调试与展示。

## 4. 功能需求（FR）

### FR-1 会话入口与鉴权
- `POST /agent/dj/stream`（需登录，body `{query}`）：SSE 事件流；未配密钥 → 立即 `error` 事件（友好文案）。

### FR-2 多 Agent 编排（四角色，单轮会话内）
- **Dispatcher（任务拆分）**：结构化输出 JSON 意图 `{scene, mood, genres[], artists[], language, count, scope(local/web/mixed), intentSummary}`。
- **Librarian（ReAct 检索）**：工具循环（≤4 次动作），动作协议 JSON `{thought, action, args}`：
  - `search_local(keyword, limit)`：本地曲库关键词检索
  - `recommend(limit)`：推荐系统 v2 个性化通道（带 reason）
  - `search_web(keyword, limit)`：歌曲海搜索（复用 ExternalMusicService/GequhaiProvider）
  - `finish(refs[])`：以工具返回的**引用下标**提名候选（防幻觉核心：模型只能引用工具给过的条目）
  - 每步产生 `thought`/`action`/`observation` 事件。
- **DJ（融合表达）**：确定性合并去重（歌名+歌手，本地优先，≤10 首）→ LLM 生成串场词（流式 text_delta）。
- **Critic（Reflection）**：对照原始需求打分 `{score, pass, feedback}`；不通过且轮次 <2 → 带反馈回炉 Librarian。

### FR-3 song_card 事件与防幻觉
- `song_card`：本地 `{songId, title, artist, cover, source:'local'}`；歌曲海 `{source:'gequhai', sourceTrackId, title, artist, cover, streamUrl, isExternal:true}`。
- 全部字段来自工具返回的数据结构，LLM 只能以 ref 提名；写操作约束沿用（外源无 songId）。

### FR-4 事件协议（SSE，event 名 → data JSON）
`stage`（阶段开始/结束）· `thought`/`action`/`observation`（ReAct 过程）· `text_delta`（串场词增量）· `song_card` · `error`（友好文案）· `done`。

### FR-5 前端 DJ 抽屉
- 全局悬浮"DJ"入口 → 右侧对话抽屉；消息 = 文本 + 卡片网格；卡片操作：播放 / 加入队列（复用外源歌曲守卫逻辑）；输入框发起新一轮。

## 5. 非功能需求（NFR）

1. 模型：`AGENT_MODEL` 可配（用户资源包主力 `glm-4.5-air`；默认仍 glm-4.5-flash）。推理模型思考耗 token——各调用给足 max_tokens，SSE 不设超时。
2. 每轮会话 LLM 调用 ≤ 10 次（Dispatcher 1 + Librarian ≤4 + DJ 1 + Critic ≤2 + 回炉）；整轮时长目标 P1 ≤ 60s（有过程可视化对冲）。
3. 密钥不落仓库（环境变量注入）；key 无效/欠费 → `error` 事件。
4. 回归底线：现有四套 E2E 全绿。

## 6. 验收标准（AC）

- AC-1 未登录调用 → 401；未配密钥 → error 事件含配置指引。
- AC-2 "来点适合下雨天听的歌" → 依次出现 stage/thought/action 事件、text_delta、≥3 张 song_card、done；卡片含本地与歌曲海两种来源。
- AC-3 所有 song_card 字段与工具返回一致（无编造 URL/ID）。
- AC-4 追问"换成周杰伦的"（P1 简化为同端点再次请求）→ 返回结果以周杰伦为主。
- AC-5 歌曲海卡片可播放、歌词封面正常；本地卡片可收藏。
- AC-6 Critic 低分回炉在事件流可见（stage: critic + librarian 第二轮）。
- AC-7 四套历史 E2E 全绿 + 新增 agent-test 通过。

## 7. 明确不做（Out of Scope，P1）

1. 多轮上下文记忆 / 口味画像 / 显式反馈（P2）。
2. CLAP 语义向量检索（P2；P1 用标签+关键词+推荐通道）。
3. Curator 采购入库（P3，对象改为用户上传/AI 生成）。
4. 逐首歌曲 reason（P1 由串场词承载；P2 细化）。
5. 工具级 Web 搜索（智谱 search-std 资源包 100 次，留作 P2 彩蛋）。

## 8. P2 增量（2026-09-06）：会话记忆 / 口味画像 / 逐首 reason / 显式反馈

- **FR-13 会话记忆**：请求携带 `sessionId`（前端每次打开抽屉生成 UUID，整个抽屉生命周期复用）；服务端内存会话库（TTL 30 分钟、上限 200 个、每会话保留最近 10 轮对话 + 上一轮已推荐歌名）。Dispatcher/Librarian/DJ 的提示词注入：对话历史（近 6 轮）+ 上轮已推荐清单（"除非用户点名，避免重复"）。SSE 首个事件 `session {sessionId}` 回传。
- **FR-14 口味画像**：由播放历史（近 50 条，JOIN song）聚合常听歌手 Top5 / 风格 Top5 / 最近播放，注入 Dispatcher/Librarian/DJ 提示词作为背景（"听众口味画像"），让"随便来点歌"类需求个性化。
- **FR-15 逐首 reason**：DJ 改为单次 call() 输出 JSON `{intro, reasons[]}`（reasons 与候选顺序对齐），intro 切片伪流式发出；song_card 携带 `reason`，前端卡片展示。
- **FR-16 显式反馈**：卡片组完成后的快捷按钮"多来点这样的 / 换个口味"——本质是携带会话记忆的预置 query，由 Dispatcher 结合历史理解。
- **AC-15**：同一 sessionId 第二轮"换成周杰伦的，多来几首" → 结果中出现周杰伦歌曲；`session` 事件返回同一 sessionId。
- **AC-16**：song_card 携带非空 reason（有 key 时）。
- 不做：CLAP 语义检索（需 Python 环境，独立排期）；智谱 search-std 联网工具（资源包 100 次，P3 彩蛋）。

## 9. P3 增量（2026-09-06）：可视化密钥配置板块（BYOK）+ 会话记忆持久化

**背景**：上线后是多用户使用，AI 会话改为 **BYOK（Bring Your Own Key）**——每个用户配置自己的模型密钥后才能使用 DJ；未配置时明确提示"当前用户还没有配置密钥，无法使用"。全局 AGENT_API_KEY 不再作为兜底（站点不做贴钱方）。

- **FR-17 密钥配置（可视化）**：DJ 抽屉内"设置"对话框——字段：API Key（密码框）、接口地址（默认智谱 `https://open.bigmodel.cn/api/paas/v4`）、模型（默认 `glm-4.5-flash`）；操作：保存 / 测试连接（真实最小调用并显示耗时）/ 清除配置。状态明示（已配置 model@host / 未配置）。
- **FR-18 配置存储**：`tb_user_ai_config`（userId 唯一）；API Key **AES/GCM 加密落库**（密钥由 JWT_SECRET 派生）；GET 只返回脱敏形式（前 4 后 4）；DELETE 清除。
- **FR-19 按用户动态客户端**：每次会话按用户配置解析 (apiKey, baseUrl, model) → `ChatClientFactory` 构建并缓存 ChatClient（键=配置摘要，上限 50）；无配置 → error 事件"当前用户还没有配置密钥，无法使用"。
- **FR-20 会话记忆持久化**：`tb_dj_chat_message`（userId/sessionId/role/content/titlesJson/createTime）替代内存会话库——重启不丢；TTL 30 分钟（读取时清理过期）、每会话保留最近 40 条；lastTitles 由最近一条带 titlesJson 的 DJ 消息派生。
- **AC-17**：未配置用户调用 → error 事件含"还没有配置密钥"；配置后同用户可正常出卡片。
- **AC-18**：GET /agent/config 返回 configured=true 且 key 脱敏；DELETE 后 configured=false。
- **AC-19**：POST /agent/config/test 用正确密钥返回 ok=true（含耗时）；错误密钥返回 ok=false。
- **AC-20**：后端重启后同 sessionId 继续对话仍有记忆（持久化生效；人工验证）。
- 明确不做：多提供商适配层之外的复杂路由；密钥分权（管理员代配）；CLAP（独立排期）。

## 10. 能力扩展第一批（2026-09-08）：播放控制 / 知识问答 / 歌单生成

**架构**：Dispatcher 意图 JSON 新增 `capability` 字段（`recommend` 默认 / `player` / `info` / `playlist`），编排器按能力路由到对应分支——推荐链路（Librarian→DJ→Critic）不变，新能力走轻量分支（不跑 ReAct，1~2 次 LLM 调用）。

- **FR-21 播放控制（player）**：用户说"播放周杰伦的晴天 / 下一首 / 声音小一点 / 单曲循环"等 → 工具 `player_control(command, ref?)`。命令集：play/pause/next/prev/volume_up/volume_down/mode_list/mode_random/mode_single/queue_clear/play_ref（按 ref 播放指定歌）。执行结果通过 **`player_command` 事件**下发前端由播放器 store 执行（点歌即播管道复用）。
- **FR-22 知识问答（info）**：歌曲信息/歌词问答 → 工具 `song_info(trackId)`（歌曲海 /play 页：年份/专辑/歌词全文）+ `lyric_search(keyword)`（歌曲海按歌词内文搜歌）。回答以 **`info_answer` 事件**输出（text_delta 流式 + 文本内嵌引用）；歌词片段附带"播放并跳到这句"按钮（`player_command` 带 seekTo 时间戳）。
- **FR-23 歌单生成（playlist）**：把推荐结果存为本地歌单 → 工具 `create_playlist(name, refs)`（仅本地 songId 可入；外源歌跳过并说明）。结果 **`playlist_created` 事件**（playlistId/name/count），前端提示 + 可跳转。
- **FR-24 意图兜底**：capability 识别失败或工具不可用时回落 recommend 链路；播放控制在无播放器状态时（如未登录设备首开）返回友好说明。
- **AC-21**："播放晴天"→ player_command 事件 + 播放器实际切歌。
- **AC-22**："晴天是哪年的歌"→ info_answer 含年份信息且引用真实数据（不编造）。
- **AC-23**："把这组存成歌单"→ playlist_created 事件 + 歌单在"我的音乐"可见。
- 安全：播放控制只影响当前用户自己的播放器（事件经 SSE 本人连接下发）；歌单创建走既有鉴权 API。

## 11. P4 增量（2026-09-11）：AI 配置从 BYOK 改为管理员统一配置

**背景**：站点实际使用者为家人/亲近朋友，让每位用户自己配密钥的体验成本过高（她打开 DJ 还要先去搞 API Key）。改为**管理员统一配置一份全局 AI 连接**，其他用户直接使用；管理员账号已有的配置自动迁移为全局配置，无需重填。

- **FR-25 全局配置行**：`tb_user_ai_config` 中 userId=0 的行作为全局配置（GLOBAL_USER_ID=0，普通用户不可能有该 ID）；管理员保存/清除/测试配置均操作该行。
- **FR-26 配置权限**：GET /agent/config 任何登录用户可看（脱敏）；POST/DELETE /agent/config 仅管理员（非管理员返回 403 文案"AI 连接由管理员统一配置"）。GET /agent/config/models 任何登录用户可用（未传 key 时用全局配置的密钥，便于普通用户浏览模型列表）。
- **FR-27 会话解析**：AgentOrchestrator 解析配置时优先全局行（userId=0）；无全局行时回退兼容读 admin 账号（role=admin 的第一个用户）自己的配置行——管理员旧配置无缝生效；两者皆无 → 既有友好提示（提示文案改为"管理员还没有配置 AI 连接"）。
- **FR-28 前端 DjDrawer**：配置入口（⚙）仅对管理员显示；普通用户不再看到"去配置"提示与设置对话框，未配置时 DJ 直接返回后端错误文案。
- **AC-24**：管理员配置全局连接 → 普通用户（无个人配置行）开 DJ 正常出卡片。
- **AC-25**：普通用户 POST /agent/config → 403/400 错误，配置不落库。
- **AC-26**：管理员此前在 BYOK 时期保存的配置（admin 账号个人行）无需任何操作，升级后继续生效（回退读取）。
- **迁移说明**：不写数据迁移脚本；resolve() 的回退逻辑天然兼容。管理员下次保存时写入全局行，旧个人行保留不碍事。
- 明确不做：多套全局配置/按用户覆盖（一份全局即可）；配置审计日志。

## 12. P5 增量（2026-09-12）：抽屉去配置入口 + 多模态输入（看图点歌）

**背景**：P4 把配置收进「管理后台 → 系统设置」后，DJ 抽屉右上角的「AI 连接」入口成为冗余且易混淆；同时用户希望"发一张图让 DJ 按画面点歌"。

- **FR-29 抽屉去配置化**：移除抽屉内 ⚙「AI 连接」按钮与设置对话框（死代码一并清理）；头部保留只读状态徽标「AI 已就绪 / AI 未配置」（全员可见，不可点击；tooltip 指向 管理后台 → 系统设置）。未配置时错误文案统一为"管理员还没有配置 AI 连接…在 管理后台 → 系统设置 完成"。**AI 连接的唯一配置入口 = 系统设置面板。**
- **FR-30 多模态输入**：输入区新增附图按钮（≤3 张，仅图片）；前端 canvas 压缩至 ≤1024px JPEG q0.82（单张 ≈两三百 KB）以 data URL 随 SSE 请求体发送；发送前可预览/删除；用户气泡展示缩略图；重试按钮沿用原消息附图。支持纯图发送（无文字）。
- **FR-31 视觉理解管道**：图片只进 Dispatcher（意图拆解）——LlmStreamClient 新增多模态重载，user content 升级为 OpenAI 视觉格式数组（text + image_url data URL）；Dispatcher 提示词要求把画面内容写进意图 JSON 新字段 `imageSummary`（无图填空串）；编排器把 imageSummary 以"用户附了图片，画面内容：…"文本注入下游（Librarian/DJ/Critic 仍纯文本，管道零改动）。后端二次校验：≤3 张、data:image/ 前缀、单张 ≤1.5M 字符，不合规忽略。
- **FR-32 视觉能力缺失的降级**：模型不支持看图导致 Dispatcher 失败时，error 事件给出可操作指引（"换视觉模型 glm-4.5v / glm-4v-plus，或去掉图片重试"）。
- **AC-27**：抽屉头部无配置入口，徽标状态与系统设置一致；系统设置保存后重开抽屉徽标刷新。
- **AC-28**：附图"看看这张图配什么歌" → 正常出卡片，推荐与画面内容相关（有 key 且为视觉模型时人工验证）；纯文字会话行为不变。
- **AC-29**：非视觉模型 + 附图 → error 事件含视觉模型切换指引，DJ 纯文字链路不受影响。
- **AC-30**：纯图发送（无文字）不再被"跟 DJ 说点想听什么吧"拦截；超 3 张/超大图被前端拦截或后端忽略。
- 明确不做：图片持久化（会话记忆仅存文字）；多图逐张理解对比；视频输入。

### P5.1 追加（同日）：改名「奶包」+ 状态徽标修复

- **FR-33 改名**：Agent 更名「奶包」（物种仍是小羊驼）——抽屉标题/输入框提示/空态文案/阶段文案（"奶包在自我质检…"）/悬浮入口与侧边栏菜单/系统设置卡片/后端错误文案全部同步；IDENTITY 提示词改为"你叫奶包……自称奶包"，串场词自然自称但不生硬重复。代码内注释与类名（DjDrawer/DjTools 等）保留 DJ 命名（技术标识不随显示名变更）。
- **FR-34 状态徽标修复**：GET /agent/config 的状态视图与 resolve() 同源——全局行不存在时回退展示 admin 账号旧配置行（source=admin-legacy），消除"DJ 明明能用却显示未配置"；抽屉每轮对话结束自动刷新徽标（finally → loadConfig），系统设置里的改动即刻反映；徽标加载完成前不渲染文字（避免闪现"未配置"）。
- **配套**：系统设置面板首次保存时若全局行不存在且 Key 留空，自动迁移 admin 旧配置行的密钥（管理员只改模型/地址不必重贴 Key）。
- **AC-31**：管理员在旧版抽屉配置过（admin 名下）而未在系统设置保存过 → 徽标与面板均显示已配置（source=admin-legacy），DJ 可用；此时在面板只改模型不填 Key 保存 → 全局行生成且旧 Key 迁移成功，会话正常。
- **AC-32**：界面与串场词以"奶包"自称；抽屉打开即徽标正确，改动配置后下一轮对话结束徽标刷新。
- **更正（同日）**：奶包是**白色长毛猫**（非小羊驼；用户提供本猫照片，即站点 favicon）。身份提示词与前端拥抱动画/FAB 形象已按猫同步。
