# 系统设置 v1 · 需求规格 + 技术设计（SDD，单文件）

> 背景：婉婉小屋上传素材时暴露 `OSS InvalidAccessKeyId`（环境变量里的 AccessKey 已失效），报错还是原始 XML。决策：**阿里云 OSS 配置做成可视化面板**（运行时可改、即时生效、无需重启/重部署），**DJ Agent 模型配置也集中进来**，放在管理后台专门的一个板块——只有管理员可见。
> 上游：婉婉小屋 v1（上传链路）、agent-v1 §11 P4（DJ 全局配置，本规格把它并入系统设置板块的 UI 入口）。

## 1. 目标（FR）

### FR-1 「系统设置」板块（/admin 新 tab，仅管理员）
- 管理后台新增「系统设置」tab，两张配置卡：**OSS 对象存储**、**DJ Agent 模型**。页面本身在 /admin 下，天然仅管理员可见；后端接口另有独立 ADMIN 角色控制（纵深防御）。

### FR-2 OSS 配置可视化
- 字段：Endpoint、AccessKeyId、AccessKeySecret（密码框）、BucketName、URL 前缀。
- 状态行明示：当前来源（**面板保存** / **application.yml 默认**）、AccessKeyId 脱敏（前 4 后 4）、Secret 只显示"已配置"。
- 操作：保存（Secret 留空=沿用旧值，首次必填）、测试连接（真实调用 OSS getBucketInfo，显示耗时与友好错误）、恢复默认（删除面板行，回退 yml）。
- **运行时生效**：OSSUtil 每次上传/删除前从配置解析，保存即生效，无需重启。
- 存储加密：AccessKeyId/Secret AES/GCM 加密落库（复用 AiCryptoUtil，密钥由 JWT_SECRET 派生）；任何接口不回传明文。

### FR-3 DJ Agent 模型配置（并入板块）
- 字段与能力与 DJ 抽屉 ⚙ 完全一致（厂商预设/接口地址/模型实时列表/思考模式），操作：保存/测试连接/清除。数据层复用 `tb_user_ai_config` 全局行（userId=0），抽屉与系统设置两处入口改的是同一份配置。
- 厂商预设列表提取为共享常量（`utils/aiProviders.js`），DjDrawer 与系统设置共用，避免双处维护。

### FR-4 上传错误友好化
- OSS 相关上传（头像/封面/音频/小屋素材）失败时，按错误码映射为可操作的中文提示（InvalidAccessKeyId → "AccessKey 无效，请到 管理后台 → 系统设置 检查"；SignatureDoesNotMatch → Secret 不正确；NoSuchBucket → 桶不存在；网络超时 → 检查 Endpoint）。不再吐原始 XML。

## 2. 技术设计

### 后端新增
| 文件 | 职责 |
|---|---|
| entity/SystemConfig.java | `tb_system_config`：configKey 唯一 + configValue(TEXT，密钥类加密) + updateTime |
| repository/SystemConfigRepository.java | findByConfigKeyStartingWith、findByConfigKey、deleteByConfigKeyStartingWith |
| service/SystemConfigService.java | OSS 配置解析（DB 行覆盖 yml 默认）、保存/重置、连接测试；@Value 注入 yml 默认值 |
| controller/SystemConfigController.java | /system/config/oss GET(脱敏)/PUT/POST test/DELETE reset |

### OSSUtil 改造
- 去掉 @Value 字段，改为注入 SystemConfigService，uploadFile/deleteFile 每次调用 `resolveOss()` 取配置（管理端低频写，单表 5 行查询，无需缓存）。
- 新增静态 `friendlyOssError(String raw)` 供各上传接口 catch 复用。

### 安全
- SecurityConfig：`/system/config/**`、`/api/system/config/**` → hasRole("ADMIN")。
- 脱敏：ak 前4后4；sk 永不回传（仅 hasSecret 布尔）。测试接口可传覆盖值（临时用，不落库）。

### 前端新增
| 文件 | 职责 |
|---|---|
| utils/aiProviders.js | PROVIDER_PRESETS 共享常量（从 DjDrawer 提取） |
| api/systemConfig.js | OSS 配置四个接口封装 |
| components/admin/SystemSettingsPanel.vue | 两张配置卡（OSS + DJ 模型），复用 modelList 拉取 |

改动：Admin.vue +「系统设置」tab（icon: Setting）；DjDrawer.vue 预设改 import。

## 3. 验收标准（AC）
- AC-1 非管理员 GET/PUT /system/config/oss → 403。
- AC-2 未配置时 GET 返回 configured=false + yml 默认值；保存后 configured=true 且 ak 脱敏、无明文。
- AC-3 保存错误 AccessKey → 测试连接返回友好失败信息（含错误码语义）；换成有效 Key 后测试通过且**上传立即恢复可用**（无需重启）。
- AC-4 「恢复默认」后 GET 回到 configured=false。
- AC-5 小屋素材上传用错误 Key 时报错为友好中文提示（不再是 XML 墙）。
- AC-6 系统设置里的 DJ 模型配置与 DJ 抽屉展示一致（同源全局行）：一处保存、两处可见。
- AC-7 前端 build 通过；既有四套 E2E 不受影响（纯新增）。

## 4. 明确不做（P1）
- 数据库/邮件/第三方等其他系统配置项（按需再加行）。
- 配置变更审计日志；多 bucket/多存储后端。
- DJ 配置分权（非管理员只读视图已由徽标承担）。
