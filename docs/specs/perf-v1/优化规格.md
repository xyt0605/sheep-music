# perf-v1：性能与体验优化（四项）

日期：2026-09-05 ｜ 状态：已实施 ｜ 回归基线：api 111 + rec 20 + ws 7

## 背景

全站功能改造完成后，遗留四个性能/配置问题：首屏 JS 1.6MB（Element Plus 全量引入 + 293 个图标全量注册）、`show-sql: true` 常开、`ddl-auto: update` 不可按环境覆盖、`ArtistService.findAll()` 与公开歌手搜索两处全表扫描、列表页直接加载 OSS 原图。

## 需求与方案

### ① 首屏包体瘦身
- Element Plus 由全量引入改为按需引入：`unplugin-auto-import` + `unplugin-vue-components` + `ElementPlusResolver`（devDependencies，不改变组件用法）。
- 图标：全量注册（293 个）改为按模板实际使用清单注册（50 个），集中在 `src/plugins/element-icons.js`。
- 指令：`v-loading` 在 main.js 手动注册（`ElLoadingDirective`）；未用到的 infinite-scroll/popover 不注册。
- 服务式组件（ElMessage/ElMessageBox/ElNotification 均为显式 import）样式通过 `src/plugins/element-styles.js` 显式引入对应 style/css。
- 验收：`npm run build` 成功；主 chunk（index-*.js）显著缩小（目标 < 700KB）；登录/首页/管理后台/播放器浏览器实测无缺样式、无缺图标、无控制台报错。

### ② SQL/DDL 配置
- `show-sql: false`；`ddl-auto` 改为 `${JPA_DDL_AUTO:update}` 环境变量可覆盖（生产可设 validate，开发默认 update 保持现有行为）。
- 验收：后端编译通过，E2E 全量回归通过。

### ③ 歌手全表查询治理
- `@EnableCaching`（ConcurrentMapCache）；`getAllArtists()` 加 `@Cacheable("artist:all")`，create/update/delete/importArtists/getOrCreateByName 全部 `@CacheEvict(allEntries=true)`——歌手只经这些入口变更，无需 TTL。
- `PublicArtistController.searchArtists()` 由"全表加载 + 内存过滤"改为 repository 条件查询（name 或 description 包含关键字）。
- 验收：E2E 回归通过；管理后台歌手下拉/导入中心/公开搜索行为不变。

### ④ OSS 缩略图
- 新增 `src/utils/image.js` 的 `ossThumb(url, width)`：仅对 `sheepmusic.oss-cn-hangzhou.aliyuncs.com`（含 `/api/oss/`、`/oss/` 代理形式）追加 `x-oss-process=image/resize,w_{width}`，外站图片（baidu/QQ）原样返回。
- 应用于列表/卡片类场景：首页卡架、歌手网格、管理后台表格、搜索/排行/我的音乐/收藏/歌单列表，头像 96~100、封面 200~300。
- 播放器/动态背景（canvas 需 crossorigin 完整图）不改。
- 验收：列表页 img 请求 URL 带 x-oss-process 且返回 200 图片；外站头像不受影响。

## 明确不做（本规格外）

- Element Plus 版本升级 / Spring Boot 升级 / 轻量 VO 投影（缓存后全表实体仅启动后首次查询一次，投影收益边际，且改响应结构有消费方风险）。
