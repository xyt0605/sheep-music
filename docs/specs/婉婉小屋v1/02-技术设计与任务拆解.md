# 婉婉小屋 v1 · 技术设计与任务拆解（SDD-Design & Tasks）

## 1. 总体架构

```
登录用户 ── /memories 展示页（粉嫩风 + 瀑布流 + 灯箱 + 星星）
                  │ GET /memory/list（登录）
                  │ POST /memory/star/{itemId} toggle（登录）
管理员 ── /admin 记忆管理 tab
                  │ GET/POST/PUT/DELETE /memory/admin/**（ADMIN）
                  │ POST /upload/memory（ADMIN，video ≤200MB）
后端   MemoryController（展示，登录） + MemoryAdminController（ADMIN）
       MemoryItem / MemoryStar 实体 + Repository
       MemoryService（todayPick 确定性挑选 + 星星统计）
OSS   memory/ 目录（图片 + 视频）；删除素材时同步删除对象
```

## 2. 关键设计决策

1. **单独板块而非复用 Moments**：Moments 是社交实体（可见范围/评论/他人点赞），语义与情感容器不符；新建两张表代价低且可长期演进。
2. **不做 private 档（用户决策）**：素材对所有登录用户开放；下架（draft）作为唯一的隐藏手段，仅管理端可见。因此砍掉 tb_memory_setting / dedicatedUserId / 可见性过滤整条链路，展示逻辑更简单。
3. **todayPick 确定性公式**：`list[epochDay % list.size()]`，服务端算好返回，前端无需二次逻辑；无素材隐藏卡片。同日稳定、跨日轮换，语义是"今天的瞬间"不是"随机盲盒"。
4. **视频直接走 OSS 公开读**：P1 不做转码与私有签名（引导素材 ≤1 分钟 1080p，200MB 上限）。上传用 `metadata.setContentLength` + 流式读取，OSSUtil 已满足。
5. **不新建播放管道**：灯箱 ♪ 直接调 player store 的 play；歌曲删除的孤儿引用由冗余字段判空兜底（songId 在但冗余字段空则隐藏 ♪）。
6. **粉嫩风的作用域隔离**：页面容器加 `memories-scope` class + 页级 CSS 变量（`--mem-*`：粉底 #fff5f7、主粉 #ff8fab、深梅 #c9184a、奶油 #ffe5ec 等），暖粉色调只在小屋内生效，避免污染 galaxy 主题与暗色模式适配；粒子用漂浮花瓣/爱心（canvas，≤30 个）。
7. **服务卡片位置**：Admin.vue 增加「记忆管理」tab（与导入中心/歌手/歌曲并列），复用后台既有卡片风格（studio.css）。
8. **前端拆分**：展示页一个 view + MemoryLightbox（含 ♪/星星）+ MemoryManagePanel（后台 tab），不引入三方图库组件。

## 3. 后端新增（com.example.sheepmusic）

| 文件 | 职责 |
|---|---|
| entity/MemoryItem.java | 素材实体（FR-1 字段） |
| entity/MemoryStar.java | 星星实体（唯一键 itemId+userId） |
| repository/MemoryItemRepository.java | findByStatus、按日期排序 |
| repository/MemoryStarRepository.java | countByUserId、existsByItemIdAndUserId、近 14 天记录 |
| service/MemoryService.java | todayPick、星星 toggle、星星动态、OSS 删除联动 |
| controller/MemoryController.java | GET /memory/list、POST /memory/star/{id} |
| controller/MemoryAdminController.java | /memory/admin CRUD + star-feed |

接口明细（均返回 Result<T>）：

- GET `/memory/list` → `todayPick` + `groups[{month, items[]}]` + `myStarCount` + `total`（登录用户视角，仅 published）。
- POST `/memory/star/{itemId}` → toggle，返回 `{starred, myStarCount}`。
- `/memory/admin/**`（ADMIN）：list（全量含 draft）、create（接收 mediaUrl 引用前端已上传的 OSS URL）、update、delete（DB + OSS 对象）、publish/unpublish、star-feed（近 14 天）。

## 4.2 后台管理信息架构

```
/memory/admin（Admin.vue 新 tab「记忆管理」）
├ 素材列表（缩略图/配文/日期/绑定歌/状态 + 编辑/上下架/删除）
├ 上传对话框：选文件（批量）→ 逐个传 OSS（进度）→ 补元信息 → 保存
└ 星星动态：近 14 天点亮记录（"9/11 婉婉点亮了「海边的风」"）
```

实现要点：

- MemoryLightbox 键盘 ←/→ 切换、ESC 关闭；移动端下滑关闭手势（translateY 阈值判定）。
- 视频卡片 preload="metadata" 显示首帧；灯箱内视频点击播放、绝不自动出声。
- 漂浮花瓣/爱心 canvas：requestAnimationFrame + 30 粒子上限 + prefers-reduced-motion 检测跳过。
- 每日瞬间卡与灯箱共用星星组件逻辑（toggle 接口幂等返回状态）。

## 5. 任务拆解

**T1 后端数据层**（0.5h）：两实体 + 两 Repository；init.sql 补注释。
**T2 后端展示接口**（1h）：MemoryController + MemoryService（todayPick、星星 toggle）。
**T3 后端管理接口**（1.5h）：MemoryAdminController CRUD + star-feed + OSS 删除联动；/upload/memory（视频校验集合 + 200MB）。
**T4 multipart 配置**（5min）：application.yml 上调；回归头像/封面/音乐上传自校验。
**T5 前端展示页**（3h）：Memories.vue + MemoryLightbox.vue（键盘/手势/♪/星星）+ 粉嫩主题作用域 + 花瓣粒子。
**T6 管理面板**（2.5h）：MemoryManagePanel + MemoryUploadDialog（复用 SongSelector）+ Admin.vue 挂 tab。
**T7 路由与入口**（10min）：router + Layout menuItems。
**T8 联调与验收**（1.5h）：按 AC-1~8 走查。
**T9 规格回填**（15min）：两份 spec 文档终稿归档。

总计约 10.5 小时。串行依赖：T1→T2/T3→T5/T6→T8；T4 可与 T3 并行。

## 6. 风险与回退

| 风险 | 概率 | 处置 |
|---|---|---|
| 200MB multipart 导致上传超时/内存压力 | 中 | 前端直传 OSS（P2 优化）；P1 引导素材 ≤1 分钟短视频 |
| OSS 公开读 URL 泄露风险 | 中 | P2 切私有 bucket + 签名 URL（有效期 1h） |
| 视频 MOV（quicktime）浏览器兼容 | 低 | 前端提示推荐 mp4/webm |
| 删除素材 OSS 联动失败 | 低 | deleteFile 失败仅记日志不阻断 DB 删除 |
| 情感场景过度设计 | — | 每个元素对应 §3 一条原则，新增元素需先入规格 |
| 星星数据被滥用为"催更"压力 | — | 明确数据仅管理员可见，不做提醒/推送 |
| 粉嫩风与暗色模式冲突 | 中 | 小屋页固定粉色浅色系（明暗切换不影响小屋）；粒子/阴影在浅色底调优 |

## 8. 运维备注

1. 素材上传走管理端（唯一入口），不会出现用户端上传流量。
2. OSS 目录 `memory/`，按需在 OSS 控制台按前缀检索运维。删除素材时同步删 OSS 对象；DB 删除失败回滚（@Transactional）。
3. 星星动态保留全量（不清理），仅展示近 14 天。
