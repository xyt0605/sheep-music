# 曲库供应链 v1 · 需求规格（SDD-Spec）

> 路线 A：合规开放曲库（Jamendo）作为"联网搜索歌曲"的第一批供给，接入现有搜索页与播放器。
> 上游决策记录见 `docs/交接文档.md` §14；agent 工作流（Librarian 挂 `search_web` 工具）在 agent-v1 规格中引用本规格的接口契约。

## 1. 背景与问题

1. 本地曲库仅 184 首，且大量歌曲音频 OSS 对象已失效（交接文档 §7.4），内容供给是当前最大短板。
2. 既定的曲库供应链原则是**全部合规**：开放曲库（Jamendo/FMA/CC0 数据集）、AI 生成原创、用户上传（§14 与 agent 调研记录）。
3. "联网搜索歌曲"要成为产品能力（搜索页）与 agent 能力（工具）的共同底座，必须先有稳定、统一、合规的**外源接入层**。
4. 聚合站路线（gequhai 类）经可行性评估（2026-09-06）明确为**仅实验性试听、不进供应链、不入库**，本规格不实现。

## 2. 目标（Goal）

1. 建立可扩展的外源音源抽象（`MusicSourceProvider`），v1 落地 Jamendo 一个实现。
2. 用户在搜索页即可搜索并**试听**开放曲库歌曲，播放体验与本地歌曲一致（同一播放器、同一队列）。
3. 全链路合规可追溯：结果页展示 CC 授权信息；外源歌曲不落库、不可收藏/评论/分享。
4. 未配置音源密钥时功能优雅降级（不报错、给配置指引），不阻塞其余功能。

## 3. 用户故事

1. 作为听众，我在搜索页搜"calm piano"，除了本地结果，还能看到开放曲库的匹配歌曲，点一下就能试听，喜欢就加入播放队列。
2. 作为听众，我能一眼区分哪些结果来自本地曲库、哪些来自开放曲库（来源标签 + CC 授权标识）。
3. 作为管理员，我只配置一个 `JAMENDO_CLIENT_ID` 环境变量就能开通该功能；不配置时站点一切照旧。
4. （未来）作为 agent-v1 的 Librarian，我可以调用与搜索页相同的服务接口检索外源歌曲。

## 4. 功能需求（FR）

### FR-1 外源音源抽象
- 后端定义 `MusicSourceProvider` SPI：`source()`（标识）、`label()`（展示名）、`isEnabled()`、`search(keyword, page, size)`、`resolveStreamUrl(trackId)`。
- 新增音源 = 新增一个 Provider 实现 + 配置项，搜索页分区自动扩展，不改既有代码。

### FR-2 Jamendo 搜索
- 对接 Jamendo v3 公开 API（`api.jamendo.com`），按关键词分页搜索曲目。
- 结果字段映射为统一 VO：外部 ID、标题、歌手、专辑、封面、时长（秒）、CC 授权名称与链接。
- 上游失败/超时/限频不冒泡为 500：返回降级结果（enabled=true、items 空、message 说明原因）。

### FR-3 流式代理播放
- 外源音频经后端代理端点同源化输出（原因见设计文档决策 D1：Jamendo CDN 无 CORS 头，前端 `crossOrigin='anonymous'` + Web Audio 可视化会拒载/静音）。
- 支持 HTTP Range 请求透传（进度条拖动必需）。
- 代理目标仅限 Provider 内置白名单域名（防开放代理/SSRF），trackId 格式校验。

### FR-4 搜索页分区
- "单曲"搜索结果按来源分区展示：**本地曲库**（现状不变）+ **开放曲库**（新增，每个已启用 Provider 一区）。
- 外源结果项提供：播放、加入播放队列两个操作；展示来源与授权标识。
- 功能未启用时该分区显示配置指引，不显示报错。

### FR-5 播放与队列行为
- 外源歌曲与本地歌曲共用播放器与播放队列；切歌、随机、循环、队列抽屉全部正常。
- 外源歌曲**不产生**后端写操作：不记播放次数、不写播放历史（`song.isExternal` 守卫）。
- 播放器"评论/分享"按钮对外源歌曲禁用（无本地 songId，与"写操作只认 songId"原则一致）。
- 外源歌曲无歌词：歌词面板显示"暂无歌词"。

### FR-6 接口契约（本次新增）
```
GET /music/external/search          （需登录，与本地搜索一致）
  ?source=jamendo&keyword={kw}&page=0&size=20
  → Result<ExternalSearchResultVO>
  ExternalSearchResultVO: { source, sourceLabel, enabled, message, total, items[] }
  ExternalSongVO: { sourceTrackId, title, artist, album, cover, duration,
                    streamUrl, downloadUrl, licenseName, licenseUrl }

GET /music/external/stream          （免登录：<audio> 无法携带 JWT）
  ?source=jamendo&trackId={numericId}
  → 音频字节流（透传上游 200/206 与 Content-Range/Content-Type）
  错误：非法参数 400；上游失败 502
```

## 5. 非功能需求（NFR）

1. **配置**：`JAMENDO_CLIENT_ID` 环境变量；缺省为空 → Provider disabled，应用正常启动。
2. **容错**：上游连接/读取超时（5s/8s）必须配置；上游异常统一降级，不影响本地搜索。
3. **安全**：代理端点仅允许数字 trackId 与内置域名白名单；搜索端点鉴权与 `/music/search` 一致。
4. **回归底线**：历史 E2E（api 111 / rec 20 / ws 7）全量不破。

## 6. 验收标准（Acceptance Criteria）

- AC-1 未登录调用 `/music/external/search` 返回 401 JSON。
- AC-2 已登录、未配置 client_id：返回 `code=200, enabled=false`，message 为配置指引，items 为空数组。
- AC-3 已登录、keyword 缺失/空白：返回 400 业务码，不触发上游调用。
- AC-4 非法 source：返回 400 业务码。
- AC-5 `/music/external/stream` 对非法 trackId（非数字）返回 400；未知 source 返回 400。
- AC-6 stream 端点免登录可访问（401 不允许出现在该端点）。
- AC-7 搜索页出现两个分区；外源歌曲可播放、可加入队列、队列内切歌正常。
- AC-8 外源歌曲播放时不产生播放次数/历史写操作（后端无对应请求）。
- AC-9 外源歌曲的评论/分享按钮为禁用态。
- AC-10（有真实 client_id 时人工验收）搜索有结果、封面/时长/授权标识正确、音频可拖动进度条。

## 7. 明确不做（Out of Scope）

1. gequhai 等聚合站接入（经评估仅可实验性试听，与合规原则冲突，不做）。
2. Curator 采购入库（下载→打标→审核）→ agent-v1 P3。
3. FMA / CC0 数据集批量导入 → 后续独立规格。
4. 外源搜索结果缓存（当前调用量低，Jamendo API 无压力；需要时再加 TTL 缓存）。
5. 外源歌曲收藏/歌单/评论/分享（无本地 songId，写操作只认 songId）。
6. 用户搜索历史记录外源搜索（外源分区为异步旁路加载，不污染本地搜索历史）。

## 8. v1.1 追加（2026-09-06）：ccMixter 零注册源 + 音源列表接口

**背景**：Jamendo 开发者门户注册在国内环境受阻（用户无法完成注册），且 archive.org / Openverse 在部署网络不可达（DNS 污染/超时）。为让功能零配置可用，新增无密钥要求的 ccMixter 源。

- **FR-7 音源列表接口**：`GET /music/external/sources`（需登录）→ `Result<List<ExternalSourceVO{source,label,enabled}>>`，启用的源排前；前端据此动态生成搜索分区。
- **FR-8 ccMixter 源**：`source=ccmixter`，dig API（`ccmixter.org/api/query`）关键词搜索，无需任何配置。映射：upload_id/title/user_name/时长(files.ps)/license_url；同一上传多音频文件时优先标准 mp3。音频直链有 UA/Referer 防护 → 代理端按 Provider 的 `streamHeaders()` 携带浏览器 UA + Referer；streamUrl 携带 `fileId={用户名/文件名}`（安全字符集校验、禁止路径穿越）供代理拼回直链。
- **AC-11**：sources 接口未登录 401、登录后含 jamendo+ccmixter 且 enabled 标志正确、启用源排序在前。
- **AC-12**：ccmixter 搜索返回真实结果（标题/歌手/授权齐全），流代理实测 206/audio/mpeg（网络可达时联测）。
- **SPI 变更**：`resolveStreamUrl(trackId, fileHint)` 增加文件标识参数；新增默认方法 `streamHeaders()`；CC 授权名推导上移为接口静态方法 `ccLicenseName`。
- **UI 边界修复**：DesktopLyric 对外源歌曲跳过歌词接口（显示"♪ 纯音乐，请欣赏 ♪"）；模拟歌词模板选择对字符串 id 健壮化（原 `(songId||0)%len` 对字符串得 NaN 越界）。

## 9. v1.2 追加（2026-09-06）：歌曲海聚合源（用户指定）

**背景**：用户明确选择接入 gequhai.com（无需账号、有音乐和歌词）。定性延续 gequhai 可行性评估结论：**聚合试听层——不入库、不进合规供应链、仅个人使用**，搜索分区展示"聚合试听"标识（区别于开放曲库的"CC 授权"）。

- **FR-9 歌曲海源**：`source=gequhai`。搜索 `GET /s/{kw}` HTML 解析（jsoup，行=标题/歌手/play_id）；播放走"会话绑定令牌"链路：`GET /play/{id}` 提取 play_id+mp3_type → `POST /api/music`（自定义头 + 同 PHPSESSID）→ 酷我 CDN 直链（antiserver 中转时按 play.js 换取真实地址）；歌词 `GET /music/external/lyric?source=gequhai&trackId={id}` 返回 LRC 文本。
- **FR-10 前端歌词**：播放外源歌曲时异步拉取歌词写入歌曲对象，歌词面板响应式渲染（ccMixter/Jamendo 无歌词，保持"暂无歌词"）。
- **AC-13**（网络可达时联测）：搜索字段齐全、streamUrl 形态正确、歌词为 LRC 文本、流代理 206/audio/mpeg。
- **SPI**：新增 `resolveLyric(trackId)` 默认空实现、`openLicensed()` 区分授权标识；`ExternalSourceVO` 增加 `openLicense` 字段。
- **风险（已知且用户知情接受）**：源站为聚合站，授权状态不明；play_id 绑定会话/直链带时间戳签名（5 分钟缓存应对）；站点改版或风控升级会导致功能失效。**不写播放历史/次数，收藏/歌单等写操作仍只认本地 songId。**

## 10. v1.3 追加（2026-09-06）：移除 CC 授权源，仅保留歌曲海

**决策**：用户明确表示 ccMixter/Jamendo 的开放曲库内容不是想要的效果（独立音乐人内容，无主流华语歌），要求删除、只保留歌曲海聚合源。 JamendoProvider / CcmixterProvider 已删除（Git 历史可查 v1.0/v1.1 提交）。

- 音源列表现在仅返回 `gequhai`（enabled=true，openLicense=false → 分区显示"聚合试听"）
- SPI 清理：移除 `streamHeaders()` 与 `ccLicenseName()`（唯一消费者已删）；保留 `resolveLyric`/`openLicensed`
- E2E external-test 重写为 19 项：鉴权/参数校验/fileId 路径穿越拦截/音源列表单源断言/歌曲海真实联测
- 外部依赖清理：application.yml 移除 jamendo 配置块（`JAMENDO_CLIENT_ID` 不再使用）
- 前端无需改动（分区由 sources 接口驱动；"CC 授权"标签分支保留为通用逻辑，当前不触发）
