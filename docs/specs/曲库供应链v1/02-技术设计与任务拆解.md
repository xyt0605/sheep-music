# 曲库供应链 v1 · 技术设计与任务拆解（SDD-Design & Tasks）

## 1. 总体架构

```
Search.vue（单曲 tab）
 ├─ 本地曲库：searchSongs()            → /music/search        （现状不动）
 └─ 开放曲库：searchExternalSongs()    → /music/external/search（需登录）
                    │
        ExternalMusicController
                    │
        MusicSourceRegistry（Spring 注入 List<MusicSourceProvider>）
                    │
        JamendoProvider（RestClient → api.jamendo.com/v3.0）

MusicPlayer <audio src="/api/music/external/stream?source=..&trackId=..">
                    │ （vite/nginx 按 /api 反代，同源）
        ExternalMusicController#stream
                    │ （白名单域名 + 数字 trackId 校验 + Range 透传）
        prod-1.storage.jamendo.com
```

前端 `streamUrl` 直接返回**相对代理地址**（`/api/music/external/stream?...`），与现有 `/api/oss` 代理模式一致，播放器零特判。

## 2. 关键设计决策

| # | 决策 | 理由（含实测证据） |
|---|------|--------------------|
| D1 | 音频走后端流式代理，不走直链 | 实测 Jamendo CDN（prod-1.storage.jamendo.com）**不返回 `Access-Control-Allow-Origin`**（有 `Vary: Origin` 无 ACAO）；而 `player.js` initAudio 设置 `crossOrigin='anonymous'` 且 MusicVisualizer 使用 Web Audio analyser——直链会被拒载或静音。同源代理同时统一多源接入与防盗链（不暴露上游真实 URL 格式） |
| D2 | 代理实现为 302 重定向？**否**，服务端 pipe | `crossOrigin=anonymous` 的 CORS 请求跨域重定向后仍要求最终响应过 CORS，302 解决不了 D1 |
| D3 | stream 端点 permitAll | `<audio>` 元素发请求不带 Authorization 头（JWT 在 header）。与 `/api/oss` 代理同等暴露面：trackId 数字校验 + 域名白名单 + 不回源 URL，可接受 |
| D4 | 外源歌曲对象 `id = "ext:{source}:{trackId}"`（字符串） | 队列去重/切歌按 `s.id` 查找，字符串 id 天然不与本地 Long id 冲突；`isExternal` 标志驱动 store/播放器守卫 |
| D5 | 不缓存搜索结果 | 调用量低（人工搜索 + 500ms 防抖），Jamendo API 免费无压力；引入 TTL 缓存超出 v1 收益 |
| D6 | 上游异常降级为空结果 + message，不 500 | 外源是增量体验，坏了不能连累本地搜索（Promise.allSettled 前端并行） |
| D7 | 播放守卫放 player store（`if (!song.isExternal)`） | `playSongAPI(song.id)`/`addPlayHistory` 对字符串 id 必然 500；store 是所有播放入口的唯一汇聚点，一处守卫全覆盖 |
| D8 | VO 不含本地 songId，收藏/歌单/评论/分享入口全部不出现或禁用 | 落实"写操作只认 songId"原则（交接文档 §14.1 输出协议的同款约束） |

## 3. 后端设计

### 3.1 新增文件（`com.example.sheepmusic`）

| 文件 | 说明 |
|------|------|
| `service/MusicSourceProvider.java` | SPI 接口：`source()/label()/isEnabled()/search()/resolveStreamUrl()` |
| `service/MusicSourceRegistry.java` | `@Component`，注入 `List<MusicSourceProvider>`，`get(source)` / `optionalGet(source)` |
| `service/JamendoProvider.java` | Jamendo v3 实现：RestClient（connect 5s / read 8s），`/tracks/?client_id=&search=&limit=&offset=`，headers.results_count 取 total；stream URL 拼装 `https://prod-1.storage.jamendo.com/?trackid={id}&format=mp31` |
| `service/ExternalMusicService.java` | 编排：参数校验（source/keyword/size 上限）、Provider 查找、异常→降级 VO |
| `controller/ExternalMusicController.java` | `GET /music/external/search`；`GET /music/external/stream`（流式 pipe，透传 200/206、Content-Type/Length/Range） |
| `dto/ExternalSongVO.java` / `dto/ExternalSearchResultVO.java` | 契约见需求规格 FR-6 |

### 3.2 配置（application.yml）

```yaml
external:
  sources:
    jamendo:
      client-id: ${JAMENDO_CLIENT_ID:}
      api-base-url: https://api.jamendo.com/v3.0
      stream-base-url: https://prod-1.storage.jamendo.com
```

### 3.3 SecurityConfig

新增一条放行（与 `/auth/**`/`/api/auth/**` 成对惯例一致）：

```java
.requestMatchers("/music/external/stream", "/api/music/external/stream").permitAll()
```

其余 `/music/external/**` 落入 `anyRequest().authenticated()`，无需额外配置。

### 3.4 错误码

| 场景 | 行为 |
|------|------|
| keyword 空 / source 未知 / trackId 非数字 | `Result.error(400, msg)`（stream 为 HTTP 400） |
| page<0 / size 越界 | 自动收敛：page≥0、1≤size≤50（不报错） |
| Provider 未配置密钥 | `code=200, enabled=false, message="未配置 JAMENDO_CLIENT_ID..."` |
| 上游超时/非 200/解析失败 | `code=200, enabled=true, message="开放曲库暂时不可用"`（WARN 日志） |
| stream 上游失败 | HTTP 502 |

## 4. 前端设计

### 4.1 新增 `api/externalMusic.js`

`searchExternalSongs({ source='jamendo', keyword, page=0, size=20 })`，走 `utils/request.js`（自动带 JWT）。

### 4.2 Search.vue（单曲 tab 分区）

- 结果区拆两个 section：`本地曲库`（原列表，加节标题）与每个已启用源的 `开放曲库` 区（v1 仅 Jamendo）。
- `performSearch` 里本地搜索照旧；外源搜索独立 `extLoading` 状态、`allSettled` 语义（失败仅影响本分区）。
- 外源行 UI 复用 `.song-item` 样式：封面 + 标题/歌手 + 时长 + `CC` 授权徽标（title=licenseName，链接 licenseUrl）+ 来源徽标；操作按钮仅 **播放 / 加入播放队列**。
- 分区空态：enabled=false → 显示 message（配置指引）；enabled=true 且无结果 → "开放曲库中没有找到相关歌曲"。
- keyword 清空/搜索类型切换时同步清理外源状态。

### 4.3 外源歌曲对象映射（player 形状）

```js
{
  id: `ext:${vo.source}:${vo.sourceTrackId}`,
  title: vo.title,
  artists: [{ name: vo.artist }],
  cover: vo.cover,
  duration: vo.duration,
  url: vo.streamUrl,           // /api/music/external/stream?... 同源
  isExternal: true,
  source: vo.source,
  licenseName, licenseUrl
}
```

### 4.4 守卫点（3 处，全部最小侵入）

1. `store/player.js#play`：`playSongAPI` 与 `addPlayHistory` 包在 `if (!song.isExternal)` 内。
2. `MusicPlayer.vue` 评论/分享按钮：`:disabled` 追加 `|| playerStore.currentSong?.isExternal`。
3. 搜索页外源行不渲染收藏/歌单/评论相关按钮（模板层面不存在）。

歌词面板：外源歌曲 `parsedLyrics` 为空数组，显示既有空态文案（无需改动，验收时确认）。

## 6. 风险与回退

| 风险 | 缓解 |
|------|------|
| Jamendo API 变更/停服 | Provider 隔离，降级为空结果；本地搜索不受影响；可接入其他合规源替代 |
| 代理带宽（音频过自家服务器） | 个人站规模可接受；如需优化可在边界 nginx 加缓存或直链方案（需解决 CORS） |
| stream 被滥用（无鉴权） | 数字 trackId + 单一上游白名单，仅音频内容；必要时加来源限频 |
| 播放历史缺失导致推荐冷启动偏差 | 外源试听不计入推荐信号是**有意行为**（未入库歌曲不该进 CF）；入库后自然参与 |

## 8. v1.1 追加（2026-09-06）：多源分区与 ccMixter 实现要点

| 决策 | 说明 |
|------|------|
| D9 前端分区由 sources 接口驱动 | `onMounted` 拉取 `/music/external/sources` 生成 section 骨架（enabled 前置），搜索时并行旁路加载各源；新源零前端改动 |
| D10 ccMixter 直链防护绕行 | 内容路径 403 拦非浏览器 UA → SPI `streamHeaders()` 让 Provider 自带上游请求头（UA+Referer），代理默认头不变 |
| D11 ccMixter fileHint | 直链 `/content/{用户}/{文件名}` 无法仅凭 ID 推导 → streamUrl 携带相对路径 `fileId`（控制器安全校验：字符集白名单 + 禁 `..` + 长度上限），零额外上游调用，Range 天然可用 |
| D12 text/plain 响应 | ccMixter API 返回 `Content-Type: text/plain`，RestClient 按类型反序列化会失败 → 取 String 后用 ObjectMapper 解析 |
| D13 DesktopLyric 边界 | 外源歌曲无 lyric 接口 → watcher 直接置"纯音乐"；模拟歌词模板索引对字符串 id 归一化（原实现 NaN 越界抛 TypeError） |

**环境事实**：archive.org（DNS 污染）、Openverse（连接超时）在部署网络不可达，不做源；ccMixter 搜索 ~3s 响应，读超时放宽至 15s。
**真机验证**：Edge(Chromium) 30s 播放稳定无报错；ZCode 内嵌 webview（IAB）在应用内播放 ~11s 后渲染进程崩溃——裸 audio / canvas+audio / crossOrigin 隔离实验均 20s+ 稳定，判定为 webview 环境问题（该环境此前从未真实播放过音频：本地 OSS 音频全为死链），非应用缺陷。
